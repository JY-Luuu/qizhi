# 栖纸 0.2 演示与讲解

## 两分钟演示，不需要 API Key

1. 安装发布页的 Qizhi，打开“行动工坊”，点击“试用离线样例”。明确说明它是内置资料和固定结果，用于演示产品流程。
2. 查看三张待确认草稿，每张包含步骤、产出、预计时长和可点击的原文片段。点击引用，解释这次读取保存的是快照。
3. 改一个标题和预计时长；展示总预算。只有确认后才会写入任务。
4. 点击“挂上示例卡片”，回到晾衣绳。编辑其中一张，展开“行动依据”，展示保留的来源信息。
5. 回到最近的计划，展示执行记录与状态。模型未配置时不要声称刚才发生过真实模型调用。

真实模型演示时，先在“模型连接”中输入自己的兼容接口、模型 ID 和 API Key，选择 1–3 份公开或愿意发送的资料，写目标、定预算并勾选发送许可。Key 不需要展示给观众。服务商可能产生 API 费用。

## 可以深入讲的实现

- 产品取舍：为什么先做一个资料到行动的完整流程；为什么沿用原生纸片而把 AI 输出变成待确认草稿。
- 证据边界：段落 ID、PDF 页码与快照哈希；精确引文校验能发现什么，不能证明什么。
- 执行边界：模型只选择受限工具，不直接拿到任务文件的写权限；所有任务由应用统一保存。
- 数据一致性：先校验整个批次，再一次性写盘；稳定卡片 ID 让重试保留既有修改，避免重复。
- 故障恢复：保存读取快照，重启时将运行中状态改为中断；重新规划会复用快照，不伪称还原同一模型会话。
- 验证：33 项固定回归、10 种本地 HTTP 场景以及原生集成检查，各自证明什么；为什么仍需要真实模型评测和用户试用。

## 贡献与表述

桌面晾衣绳、原始视觉设计及主要应用基础来自 Hang Later；Qizhi 的个人身份与发布改造、行动工坊及对应检查通过 AI 编程辅助完成。讲解时分别说明上游基础、自己提出的产品需求、实际理解和修改过的代码，以及辅助工具承担的工作。

可以描述已经实现的来源读取、工具协议、确认机制和回归测试。尚没有真实用户留存、效率提升、商业化数据或模型质量分数；不要写成已验证成绩。适合后续由维护者独立练习的改动是：新增一种资料格式、增加一项新的失败案例，或根据用户反馈调整任务粒度，然后解释自己的验证方法。
